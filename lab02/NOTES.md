## Основные понятия Git

**Рабочая папка** — это обычная папка `cs-practice` на моём компьютере, где я редактирую файлы (`calc.py`, `NOTES.md`). Изменения в ней Git видит, но пока не сохраняет в историю. `git status` показывает, какие файлы в рабочей папке изменены.

**Индекс (staging area)** — промежуточная зона между рабочей папкой и историей. Командой `git add` я кладу в индекс те изменения, которые хочу включить в следующий коммит. Так можно коммитить файлы по отдельности: например, код и заметки разными коммитами. Убрать файл из индекса можно командой `git restore --staged`.

**Коммит** — снимок состояния проекта, который записывается в историю командой `git commit`. У коммита есть уникальный хеш, автор, дата и сообщение. К любому коммиту можно вернуться (`git restore --source`) или отменить его (`git revert`).

**Git и GitHub** — разные вещи. Git — программа для контроля версий, она работает локально на моём компьютере и хранит историю в папке `.git`. GitHub — сайт-хостинг, где лежит копия репозитория (удалённый репозиторий `origin`). Коммиты на GitHub попадают только после `git push`. Без GitHub Git работает, но копия не хранится в облаке и недоступна преподавателю.

**Ветка** — подвижный указатель на последний коммит в отдельной линии разработки. Ветка `experiment` позволила мне пробовать правку, не трогая `main`. Если результат нравится, ветку вливают в `main` командой `git merge` (с `--no-ff` создаётся отдельный коммит слияния). Если нет, ветку удаляют, а `main` остаётся нетронутым. Ветка отличается от тега тем, что двигается с каждым новым коммитом, а тег закреплён за одним коммитом навсегда.
