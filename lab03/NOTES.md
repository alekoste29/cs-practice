## 2. Сравнение версий и поиск

- `git diff HEAD~2 HEAD -- lab03/calc.py` показывает построчную разницу между двумя состояниями файла (здесь: что добавилось за два коммита).
- `git show HEAD~1` показывает один коммит целиком: автора, сообщение и его изменения.
- `git log` показывает список коммитов, то есть историю, а не содержимое правок.
- `git log -S"def"` нашёл коммиты, в которых менялось число вхождений слова `def`, то есть где добавлялись функции. Полезно, чтобы найти, когда появился или исчез фрагмент кода.
- `git blame` показал для каждой строки файла, в каком коммите и кем она написана. Нужно, чтобы понять, откуда взялась конкретная строка.
## 3. Восстановление файла

- `git restore lab03/calc.py` вернул файл к состоянию последнего коммита. Мои несохранённые правки (удалённые строки) пропали.
- `git restore --source=HEAD~2 lab03/calc.py` берёт файл не из последнего коммита, а из указанного, то есть старую версию. `git diff` показал, чем она отличается от текущей.
- Если бы я не вернул файл обратно, в рабочей папке осталась бы старая версия, и её можно было бы случайно закоммитить, потеряв новые функции. Поэтому я снова выполнил `git restore`.
## 4. Отмена ошибочного коммита

- Коммит с делением без проверки на ноль я отменил командой `git revert HEAD`. Она создаёт новый коммит, который отменяет изменения предыдущего, а старый коммит остаётся в истории.
- `git reset --hard` двигает ветку назад и удаляет коммиты из истории вместе с изменениями в файлах, то есть переписывает историю.
- В уже опубликованной (запушенной) истории безопаснее `revert`: у других людей есть копии старых коммитов, и после `reset` их история разойдётся с моей. `revert` только добавляет новый коммит, поэтому конфликтов не создаёт.
